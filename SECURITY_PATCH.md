# Temporary dependency security patch

`braces@3.0.3` has no patched release for GHSA-vfj7-8cjw-p6xm in the registry at validation time (2026-10-18). Its parser now rejects AST nesting beyond 128 levels, including braces and parentheses, before recursive compilation/stringification/expansion. Normal glob expansion and ranges remain supported. Untrusted prebuilt AST objects are outside the string-pattern API used by these build tools.

`npm ci` applies the versioned patch with `patch-package --error-on-fail`. `npm run security:check` queries the full npm audit, verifies the installed parser SHA-256 and version for the installed root `braces` package unconditionally, as well as **every reported braces installation**, runs deeply nested/unfinished/mixed pattern regressions plus valid pattern checks, and fails on any other advisory at any severity or unavailable audit. This exact advisory is considered mitigated only with that evidence. The advisory feed may report the locally patched version or temporarily omit it; neither changes the required patch validation. Report raw audit counts from the dated run instead of assuming a permanent count.

The exception expires on **2026-11-18** and must be reviewed against upstream. Remove the patch and exception when a compatible fixed release is available. The gate also fails if the patch is absent, modified, or applied to another version. Moderate selector-parser issues are addressed with 7.1.6 and the production build/E2E verify compatibility.

The `@typescript-eslint/typescript-estree` dependency uses a targeted `minimatch@11.0.8` override for GHSA-g3hv-icrc-35l4. Other dependency paths retain their compatible versions. Lint, type checking and the production build verify the parser/tooling integration on Node 24. The final 2026-11-14 audit reported zero advisories; the braces patch checks remain mandatory even when the feed is empty.
